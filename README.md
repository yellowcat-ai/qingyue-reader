# 轻阅 · 安卓本地小说阅读器

一个纯本地的小说阅读 App：导入 txt / epub / pdf / mobi / azw3，自动分章、记忆阅读位置，支持在线多音色听书，
锁屏与切后台后可以连续朗读、自动跨章。

- 安装包见 [Releases](https://github.com/yellowcat-ai/qingyue-reader/releases)
- 体积约 4.7MB（PDF 引擎 pdf.js 约 +2MB），**零 native 库**（无 `.so`），不需要安装任何第三方语音引擎
- 全部数据留在本机（IndexedDB），不联网也能读；听书时才访问语音接口

## 功能

| 模块 | 说明 |
|---|---|
| 导入 | txt（自动识别 UTF-8 / GBK / Big5）、epub、pdf（文字层抽取，抽不出的自动按页原样显示）、mobi / azw3（Kindle 格式，见下节），SAF 选择文件，缓存副本避免授权失效 |
| 分章 | 按「第 N 章」等常见标题正则切章，支持手动改编码后重新解析；PDF 优先用书签切章 |
| 阅读 | 上下滚动 / 左右翻页两种模式，字号、行距、边距、主题（纸黄/夜间/护眼）可调 |
| 记忆 | 记住每本书的章节与位置，重进直接续读；显示总进度与剩余章节 |
| 听书 | 14 个中文音色（晓晓、云希、云扬、辽宁小北、陕西小妮、粤语等）+ 百度兜底 + 系统 TTS 兜底 |
| 多角色 | 自动识别对白与说话人，一句一个音色；旁白保持所选音色，同名角色全书稳定，可手动换色 |
| 后台 | 前台服务 + 常驻通知（书名·章节·进度·停止），CPU/WiFi 唤醒锁，锁屏继续念 |
| 跨章 | 原生队列一次装载 8 章，念完一章自动进下一章，不足时回叫网页补章节 |
| 其他 | 定时关闭、语速/音调调节、当前句高亮、屏幕常亮 |

## PDF 支持

PDF 有两条读法，导入时**由结构体检自动选**（可手动切换）：

| PDF 结构 | 默认读法 | 说明 |
|---|---|---|
| 横排单栏（绝大多数小说） | **文字重排** | 抽文字层 → 分段 → 分章，与 TXT 走同一条链路，可改字号/主题、可听书、可搜索 |
| 扫描件（无文字层） | **按页原样** | 页面直接渲染成图，能看能翻；不重排、不搜索 |
| 竖排 / 多栏 | **按页原样** | 这类版面重排必然串行；若已抽出文字，可手动切回重排 |

结论直接决定阅读方式（`readMode`），也就是「体检当路由器」；详见下面的「按页原样阅读」。
这样「PDF 排版乱」不再是缺陷：乱的那类本来就不该重排。

### 按页原样阅读（v1.45）

- 连续滚动 + 适配宽度，双击或点右上角切换 1× / 1.5× / 2× / 3×
- 进度按页记忆（滑杆可拖，页码与总页数常显），书签目录直接跳页，无书签则每 10–20 页给锚点
- 按需渲染：`IntersectionObserver` 只渲染视口附近，离当前页超过 3 页的画布直接释放，
  318 页的书实测只同时存在 6 张画布；滚动时用二分查当前页，不在滚动帧里读布局
- 上限：图片型 PDF 每页按 2 倍像素渲染（再高只是吃内存）；不支持双页并排、文字搜索、听书

### 文字层抽取

pdf.js（legacy 3.11，纯 JS，无 native 库）逐页 `getTextContent`，
按基线还原行、按「首行缩进 / 相对行距突增 / 短行结尾」合并成段落，再交给和 TXT 完全相同的
分章、进度记忆、翻页、听书链路，因此 PDF 也能用全部朗读能力。

- 章节来源优先级：**PDF 书签（outline）** → 正文「第 N 章」正则 → 每 ~4000 字按页分组
- 封面：渲染首页缩略图为封面图，4 秒超时即放弃（无 GPU 环境不会卡住导入）
- 页眉页脚自动识别：在多页重复出现的首/末行直接剔除（仅对 ≤40 字的短行生效，避免误删重复的正文段落）；
  页码（`— 3 —`、`3/120`、`第 3 页`）逐段过滤；**位于页边的孤立页码行在合并段落之前就剔除**，
  否则会与正文行距相同而被当成续行拼进正文（`…光耀门` + `6` → `…光耀门6`）
- 跨页段落自动接回：上一段没有句末标点、下一段不像新段开头时，判定为同一段被分页切断；
  行末引号会先剥离再判句末，避免 `…写着“不算”` 这类段中引用被误当段尾；
  合并按「段落流」而非「页对」处理，整页只产出一段时不会因该页变空而切断后续续段
- 书名元数据若被填成章节名/版式名（`序`、`目录`、`正文`…）或「第 N 章」，改回用文件名
- 「目录」页（标题为目录且正文被虚线占满）跳过，否则听书会把「序·····1 第一章·····9」逐条念出来

### 抽取准确率（实测，非估算）

**合成样本**（以「生成 PDF 时使用的原始文本」为真值，可逐字对齐）：

| 样本 | 规模 | 字符召回 | 段落边界 |
|---|---|---|---|
| 无书签 + 页眉页脚（顶格排版） | 10 页 / 7468 字 / 12 章 | 100%（7468/7468） | 72/72 段，12/12 章全对 |
| 带 PDF 书签 | 5 页 / 3112 字 / 5 章 | 100%（3112/3112） | 30/30 段，5/5 章全对 |
| 真实排版（首行缩进 2 字、页眉页脚、长段落跨页、中英数字混排） | 10 页 / 13120 字 / 8 章 | 100%（13120/13120） | 59/59 段，8/8 章全对 |

**真实出版物**（《西游记》上，人民文学出版社整理本，343 页 / 1.25MB / 加密标记为 True 但无口令）：

| 指标 | 结果 |
|---|---|
| 解析耗时 | 1.7 秒（343 页，桌面 Chromium；移动端 WebView 约慢 2–4 倍） |
| 章节 | 51 章，书签 52 条中封面 1 条无正文自动跳过，标题与页码全部对齐 |
| 正文字数 | 389,627 字 |
| 字符召回 | 逐章与 pypdf 结果对齐，差异仅剩「主动去掉的章标题行」+ 源文件字体编码损坏的个别字（约 30 字 / 0.008%） |
| 页码/页眉残留 | 0 段 |
| 段落切分 | 未以句末标点结尾的段落占比 10.5%（改造前 31.9%） |

该样本暴露并修掉了三个真实缺陷（对应 v1.40）：

1. **书签标题与正文标题不完全一致时，章标题行去不掉**：正文作「第八回 同我佛造经传极乐…」（多一个「同」）、
   「第十四回 六贼①无踪」（带脚注序号），原实现只做字符串相等/包含判断 → 改为剥离脚注号后按 LCS 相似度 ≥80% 判定
2. **跨页续段把下一页的章标题吃进上一章末段**（`前言` 末尾挂上了「第一回…」）→ 下一页首段匹配章节标题模式时不做跨页合并
3. **诗句/引文块的悬挂偏移被当成首行缩进**，导致段中被切断（如「…既然皆己 / 心，何用别人说」）→
   缩进判据从 1.2 字收紧到 1.8 字（中文首行缩进惯例 2 字，悬挂偏移多为 1.5 字）

该书 51 章里 43 字的缩进行为「诗行块」——每行独立成段，与纸书排版一致，属于预期行为而非误判。

**真实出版物**（《围城》钱钟书，Word 2007 导出，228 页 / 2.0MB / 14 条书签，含大量命名目的地）：

| 指标 | 结果 |
|---|---|
| 解析耗时 | 1.5 秒（228 页，桌面 Chromium） |
| 章节 | 13 章（书签 14 条，其中「目录」页按噪声跳过），章名与正文对齐 |
| 正文字数 | 238,271 字 |
| 字符召回 | 逐章与 pypdf 对齐，13 章全部 99.7%–100%；缺口即主动去掉的章标题行 |
| 页码/页眉残留 | 0 段 |
| 段落切分 | 未以句末标点结尾的段落占比 **0.7%**（初版为 81.1%） |

该样本暴露并修掉了三个真实缺陷（对应 v1.41），都是「上一本测不出来」的类型：

1. **行距判据把行距和字号绑死**：这本书是 1.5 倍行距（23.3pt 行距 / 10.5pt 字号 = 2.22 倍），
   而原判据写死「行距 > 2.1 倍字号即视为段间空行」→ 每一行都被当成分段点，
   第一章切出 383 段（一行一段）。改为取**页内行距众数**做基准，
   段间空行判定为「相对常规行距 ≥1.45 倍」，与字号解耦
2. **页边页码被吸入正文**：页码在文字层且与正文行距相同，合并段落时被当成续行 →
   `…光耀门` + `6` → `…光耀门6`。改为在合并段落前先剔除首/末两行中的孤立短数字行
3. **整页只剩一段时切断续段链**：11 页零缩进页（源文件本身无缩进）会整页并成一段，
   跨页合并后该页变空，按页配对导致它与下一页的续段彻底接不上（`…光耀门` `楣，也是…`
   之间多出一个空段）→ 改为按段落流合并，并允许跨过被合并清空的页与书签标出的章节边界

需要注意：《围城》全书 6,510 行中仅 1,146 行带缩进（17.6%），另有 11 页完全没有缩进。
这些页的段落边界在 PDF 里不存在任何几何信号，整页会被并成一段（最长约 1,200 字）——
文字不会错，只是分段偏粗。

**真实出版物**（《倚天屠龙记》（一）金庸，三联版，Acrobat Distiller 4.0 生成，194 页 / 0.68MB / 12 条书签）：

| 指标 | 结果 |
|---|---|

| 章节 | 11 节（书签 12 条 = 书名 + 序 + 十章），章名与正文对齐 |
| 正文字数 | 237,672 字 / 2,081 段 |
| 字符召回 | 逐字与 pypdf 对齐 **99.93%**；缺口仅为主动去掉的 10 条章标题行 |
| 段落边界 | 与 pdfplumber 坐标独立重建的 2,081 段逐段比对：**0 漏分段、0 误分段** |
| 页码/页眉残留 | 0 段（本书无页眉页脚） |
| 异常字符 | U+FFFD 0 个；仅 2 字因源文件字体缺 ToUnicode 取到错误码位（「弥空飞扬」「阴跷库」），需人工校对 |

该样本暴露并修掉了两个缺陷（对应 v1.42）：

1. **跨页续段仅凭「上一段有无句末标点」判断**：正文一句正好写到页末（右边界顶格）且句末标点齐全时，
   原判据认定该段已结束，下一页的续段被切成新段（本书 11 处，如「…跟你试几招。”」／「说着抽出半截短剑。」）→
   `layoutPage` 改为同时输出每段的**版式标记**：`head`（首行是否缩进）、`tail`（末行是否顶到右边界）。
   跨页时优先用几何量判断：末行顶格 + 下一页首行齐左 = 续段；下一页首行缩进 = 新段（中文新段必缩进）。
   整本书缩进率低于 20% 时（无缩进排版）退回原来的纯文本判据，避免误并
2. **「书名-作者」型文件名把作者写进书名**：本书元数据无 Author，书名变成「倚天屠龙记(一)-金庸」、
   作者为空 → 元数据缺作者时按「末尾 2–3 字中文 = 作者」拆分；同时括号里的卷次「（一）」「（上）」
   不再被当版本噪声删掉（只删「精校版/全本/TXT」这类）

回归：合成样本段落数仍为 72 / 30 / 59 段，与基线一致；《西游记》《围城》样本文件已不在本地，本轮未复测。

**真实出版物**（《唐诗三百首》补注本，中华书局注疏版式，318 页 / 0.50MB / 288 条书签——**一行一段的诗集**）：

| 指标 | 结果 |
|---|---|
| 解析耗时 | 0.35 秒（318 页，桌面 Chromium） |
| 章节 | 288 章（书签一首一条） |
| 正文字数 | 120,300 字 / 2,235 段 |
| 字符召回 | 98.97%；175 处缺口几乎全是「诗题行」（已转为章名），无整段丢失 |
| 版式还原 | 每句诗独立成段、诗题独立成段、诗人小传与 ①②③ 注疏块各自成段 |
| 页码/页眉残留 | 0 段 |

该样本暴露并修掉一个缺陷（对应 v1.43）：**版心边界取了「页内众数」，整页都是短行时集体失效**。
诗集页上没有一条行顶到右边界，`right` 的众数就成了诗行宽度本身（267pt 而非版心 495pt），
于是「短行结尾」判据永不成立，缩进的众数也变成诗行左边界（123.8 而非 99.8），
整首诗被并成一段（《月下独酌》实测 157 字 1 段）。
改为**抽样 16 页（≤24 页的书抽 6 页）估计全书版心**：左边界取 5 分位、右边界取 98 分位，
每页再与页内值取「更靠外者」兜底。修后同一首诗还原为 7 句诗 + 1 段注疏。
代价约 +3–5% 解析时间（本书 345ms → 349ms），小说类输出逐字未变（倚天仍 237,672 字、
段落统计一致，合成样本仍 72/30/59）。

### 导入前结构体检（v1.44）

扫描件、竖排、多栏这三类 PDF 即便抽得出文字，阅读顺序也一定是错的。与其让用户导入之后
才发现排版乱掉，不如在导入时先说清楚。做法是抽样 12 页做只读检测，命中就给结论：

| 结论 | 触发条件 | 行为 |
|---|---|---|
| 扫描件 | 抽查页平均不足 20 字 | 跳过文字抽取，直接用按页阅读（省掉白跑几百页） |
| 竖排 | ≥50% 的抽查页是竖排 | 默认按页阅读；文字照抽，可手动切回重排 |
| 多栏 | ≥40% 的抽查页有多栏 | 默认按页阅读；文字照抽，可手动切回重排 |

判据（阈值在 511 页真实横排书上标定，正常书零误报）：

- **竖排**：文字块基线的方向偏离水平 55°–125°（旋转字）；或同一行内相邻字符间距的中位数
  达到一个字以上、且每行只有几个字（直立字逐列堆叠，旧排版工具的导出方式）。
- **多栏**：版心中部存在宽度 ≥ 14pt 的竖向空白带，穿过的行数不超过 12%（这一条专门留给
  跨栏大标题和页眉），且空白带两侧各有 ≥ 25% 的字符。

验收样本由 `test/mkstruct.py` 生成（reportlab + 黑体，`test/fixtures/` 下）：

| 样本 | 结构 | 体检结论 | 抽取结果 |
|---|---|---|---|
| struct-2col.pdf | 双栏 + 跨栏大标题 | 多栏（100% 抽查页） | 9,600 字，但左右栏被并成一行 |
| struct-vert.pdf | 竖排，整字旋转 90° | 竖排（100%） | 5,544 字，顺序错乱 |
| struct-vert2.pdf | 竖排，单字直立堆叠 | 竖排（100%） | 3,672 字，顺序错乱 |
| scan.pdf | 纯图片无文字层 | 扫描件（平均 0 字/页） | 报错「这是图片型扫描 PDF，需要先用 OCR」 |

代价：+50–70ms 解析时间（倚天 0.30→0.36 秒，唐诗 0.35→0.42 秒）；正文输出逐字未变。

限制（导入时会明确报错或降级，不会静默导入垃圾数据）：

| 情形 | 表现 |
|---|---|
| 扫描件 / 图片型 PDF | 按页原样显示，能读能翻；不做 OCR（因此没有文字搜索与听书） |
| 有密码 / DRM 的 PDF | 报「PDF 有密码保护，无法导入」；仅设了加密标记但无口令的可以正常打开 |
| 竖排（旋转字或直立字） | 默认按页原样显示；手动切回重排时文字会被抽出，但顺序可能错乱 |
| 双栏 / 多栏 | 默认按页原样显示；手动切回重排时左右栏会被并成一行 |
| 公式、表格 | 文字按单列读取，版式信息丢失（小说场景影响小） |
| 章节起始在页中间 | 该页文字整体归入新章节，前章可能少一段过渡文字 |
| 悬挂缩进的列表 / 引文 | 续行缩进会被判成新段（只影响分段，不影响文字完整性） |
| 全篇无缩进且无空行的排版 | 无任何分段信号，整页并成一段（实测《围城》11 页如此，最长约 1200 字） |
| 源文件字体编码损坏 | 个别生僻字取出来是私用区码位或错误汉字（实测 343 页约 30 字），两种抽取器都救不回来 |
| 体积 > 120MB | 直接拒绝；60MB 以上提示内存风险 |

`novel-reader/test/pdf-e2e.html` 是回归用页面：起个静态 http 服务打开它，即可看到
`test/fixtures/` 下 plain.pdf / outline.pdf / dirty.pdf / scan.pdf 四份样例
（顶格 / 带书签 / 真实缩进排版 / 扫描件）的解析结果。
`test/pdf-accuracy.html` 额外把抽取文本回传，配合真值可复算上表的召回率；
`test/pdf-real.html?f=<文件名>` 可对任意真实 PDF（放在服务目录下）跑一遍并输出章节与段落统计。

真实 PDF 的命令行回归（静态服务 + headless Chromium + 结果落盘，文件放 `test/real/`；
`fx/xxx.pdf` 表示取 `test/fixtures/` 下的文件）：

```bash
node test/real.mjs yitian.pdf "倚天屠龙记(一)-金庸.pdf" yitian        # 小说
node test/real.mjs tangshi.pdf "唐诗三百首.pdf" tangshi               # 诗集
node test/real.mjs fx/struct-2col.pdf "双栏.pdf" t-2col              # 结构体检正样本
```

## MOBI / AZW3 支持

Kindle 的两套格式实际是同一个壳：**Palm 的 PDB 数据库文件**（一段头 + 一串 record），正文是 HTML。

| 格式 | 正文模型 | 压缩 | 处理方式 |
|---|---|---|---|
| MOBI（mobi7，`.mobi` / `.prc`） | HTML 3.2 子集 | PalmDOC LZ77 或 HUFF/CDIC | 拆全部文本记录拼成一份 HTML，交 TXT 那条链路分章（有 `<mbp:pagebreak>` 时优先用库的切分） |
| AZW3（KF8，`.azw3` / `.azw`） | HTML5 分片，按 FDST + skeleton 重建 | 同上 | 逐 spine 文档抽取，章节名从目录索引反查（同一文档被多个锚点指向时取第一个） |

**DRM 会明确拒绝**：PDB 头 0x0C 处的 encryption 非 0 就直接报「带 DRM 加密，需先用 Calibre 去保护」，
不会把加密字节当正文解出一堆乱码。压缩方式只认 1（无压缩）/ 2（PalmDOC）/ 17480（HUFF/CDIC）。

**实测数据**（样本：Standard Ebooks 的 *Short Works* 三件套 + libmobi 测试集，真值用 KindleUnpack 转 EPUB 后取正文）

| 样本 | 格式 | 字数 | 真值 | 偏差 |
|---|---|---|---|---|
| epictetus.azw3 | AZW3（KF8，UTF-8） | 108,630 | 109,123 | 0.5% |
| epictetus.mobi | MOBI（PalmDOC） | 109,714 | 110,166 | 0.4% |
| sample-unicode-huffdic.mobi | MOBI（HUFF/CDIC） | 26,643 | 27,380 | 2.7% |
| sample-cp1252.mobi | MOBI（windows-1252） | 26,714 | 27,345 | 2.3% |
| sample-drm-v1.mobi | 带 DRM | — | — | 按预期拒绝导入 |

偏差来源都是被过滤掉的软连字符、页眉页脚式短行与目录页，无整段丢失。

**解析库**：`vendor/mobi/mobi-parser.js`，由 [@lingo-reader/mobi-parser](https://github.com/hhk-png/lingo-reader)（MIT）
用 esbuild 打成单文件 ESM（66KB，含 fflate），仅在导入 mobi 时动态 import，不影响启动。
许可证原文见 `vendor/mobi/LICENSE`。

**这一段踩到的三个坑**（都已修）
1. HTML 转文本按「节点列表」收集时，`<li><p>…</p></li>`、`<blockquote><p>…</p></blockquote>` 这类嵌套
   会把同一段文字数两遍 —— MOBI 实测多出 16% 字符。改成「每个块只取自己的直接文本、递归进子块」。
2. 老 MOBI 会把整本书按记录切成多个完整 HTML 文档拼接，浏览器只认第一份，`</html>` 之后的正文全丢
   （HUFF/CDIC 样本只剩 663 字、内容还是从第二份文档开始的）。检出「文档边界后仍有正文」时先把边界标签拆平。
3. 广告/水印过滤对**所有**长行生效，一段 26k 字的技术书正文因为含一个链接被整段删掉。
   改为只对 ≤120 字的短行生效（盗版站尾巴都是短行）。

**限制**：KFX（亚马逊现行私有格式）不支持；带 DRM 的书不支持；固定版式的漫画类 AZW3 只能读到文字，
图片资源不还原；mobi7 若既没有 pagebreak 也没有「第 N 章」这类标题，会按约 4000 字等分成节。

## 语音方案

App 内置了微软 Edge 在线语音（WebSocket 直连，无需 API Key、无需装引擎），
实现在 `EdgeTtsEngine.java` + `EdgeGec.java`：

- 鉴权令牌为 `Sec-MS-GEC` **v2** 格式（`CS64` + 微软变体 SHA-256，`K[14] = 0xC9DC06A7`），
  纯 Java 实现，与官方算法 20/20 对拍一致
- 遇到 403 会用响应 `Date` 头校正时钟偏差后重试一次
- 第二引擎为百度翻译语音接口（`BaiduTtsEngine.java`），音质平一些但响应快
- 仍失败则降级到系统 TTS；设备没有中文引擎时，界面上会提示切换在线音色

> 早期版本用 sherpa-onnx 做过纯离线合成，但其 `libonnxruntime.so` 为 4KB 页对齐，
> 在部分机型上反复触发 native SIGSEGV 且无法从 Java 侧拦截，已在 v1.16 整体移除。
> 如需完全离线听书，请安装系统级中文 TTS 引擎（如讯飞语记、VoxEngine）。

## 多角色朗读（v1.47）

给对白分配不同音色，旁白保持所选音色。全部本地启发式，不联网、不调模型。

识别链路在 `js/roles.js`（纯函数，可单独测）：

1. 句中有引号 → 视为带台词的句子（引号里只是「哈哈、哈哈」这种拟声的除外）；
2. 按**标点切成短句**，从最后一个短句往前找「名字 + 说话动词」——
   整串取人会粘上「一张铁青的脸更加青了」这类叙述，短句级才是真正的提示语；
   说话动词按结束位置最靠后取（避免「道 / 说道」子串重叠）；
3. 剥人名前先交替剥掉**动作尾 + 状语 + 助词**（「郭襄喜道」→郭襄、
   「更加青了，冷冷的道」→卫天望、「跳起身来，说道」→ 上一短句的主语），
   三字名的第三字不是虚词才取三字（卫天望 / 何足道），否则取两字；
4. 「对郭襄道」里的郭襄是听话人，说话人取前一个短句；
5. 只在整章出现一次的「名字」判为误切片段（郭襄心 / 暗自惊 / 道喝），退回旁白；
6. 提不到人就沿用最近一次说话人（限 3 句内），代词对白（他 / 她）按性别就近归属；
7. 名字 → 稳定哈希 → 男声池 / 女声池，同名角色全书同一个音色，且不与旁白撞色。

粒度是**整句**：带台词的句子整句用角色音色念，其余用旁白音色。
拿不准的一律退回旁白——宁可少切，不可乱切。

### 性别判断（v1.48）

旧版有两条规则会**让男角色拿到女声**，都已移除：

- 名字里只要含一个中性字（雪 / 玉 / 兰 / 红 / 美）就判女 —— 现在词表拆成
  「强性别字」（娘姐妹 / 妍媛姝 / 黛襄娥）和「弱性别字」，弱字只累计 1 分；
- 判不出来时按出场顺序「男、女、男、女」交替 —— 直接把一半男角色送进女声池。
  现在无线索一律按男性（中文小说男性角色占多数）。

现在的 `genderScore()` 是打分制，证据按可靠性排序：

| 证据 | 权重 | 例子 |
|---|---|---|
| 台词自称 | ±6 | 「在下」「妾身」「老夫」「小女子」 |
| 紧邻说话动词的代词 | ±4 | 「她笑道：」「”他说」 |
| 叙述身份名词 | ±3 | 「那少女」「那汉子」 |
| 名字强性别字 | ±3 | 黛 / 襄 / 婷；峰 / 刚 / 豪 |
| 名字弱性别字 | ±1 | 雪 / 兰 / 红 / 嫣 |
| 三字名男先验 | +1 | 仅在名字完全无线索时生效 |

两个细节容易踩错，已在注释里标明：

- **宾语位置的代词不能算**。「郭襄看着他，笑道：」的主语是郭襄，代词只取引号旁
  那一个短句（分句后剩「笑道」），否则郭襄会被判成男性；
- **姓氏不参与性别判断**。「王语嫣」的「王」、「花铁干」的「花」都不是线索。
  但首字本身是强性别字时不剥（「梅超风」的「梅」是姓也是女名字，剥了反而错）。

### 一人一音与跨章一致（v1.48）

靠 `js/rolebook.js` 的书级角色档案实现，存储键 `nr.rolebook.<bookId>`：

- **跨章一致**：角色 → 音色的映射落盘，换章、重开 App 都不变。
  旧版每章独立计算，同一个「郭襄」在 A 章拿到晓伊、B 章拿到晓萱，这是最出戏的地方；
- **跨章名字归一**：本章切成「郭襄心」而档案里是「郭襄」时并过去，
  否则同一个人会分裂成两个角色、两个声音；
- **一人一音**：Edge 普通话只有 7 个音色（3 女 4 男），一本小说十几个角色不够分。
  音色槽 = 基础音色 × 音高变体，编码成 `edge:zh-CN-YunxiNeural@-10`（云希降 10Hz），
  容量从 7 扩到 35。分配时先占满基础音色，池用尽了才叠加音高；
- **性别累积投票**：同一章反复重算不重复计票（`beginChapter` 幂等），
  跨章累积到 |score| ≥ 6 才允许翻案 —— 翻案必然换声音，不能因一两句噪声就换。

音高档位按性别定：男声 `[0, ±10, ±18]Hz`，女声 `[0, ±14, ±24]Hz`（基频不同，
同样的 Hz 幅度听感不等效）。上限控制在约 15% 以内，再大就成了娃娃音 / 低音炮。

> 音高用 Hz 而不是百分比：实测服务端接受 `pitch='+10Hz'`，
> 传 `'+10%'` 会被客户端直接拒绝（`ValueError`），见 `test/probe_pitch.py`。

面板里「重排全书音色」会清空本书档案，角色全部重新识别、重新配音。

回归测试里有一段真实小说（`test/fixtures/yitian-chap.txt`，《神雕侠侣》郭襄初遇何足道，
72 句），专门守上面几类曾经真实翻车的错误：郭襄被判成男性、把「而已 / 鼓掌 / 冷冷的」
当人名、把「何足道」截成「足道」。

原生侧（`NativeTTS.java`）配合三处：

- `Seg` 增加与句子等长的 `v`（音色）数组，队列旁挂一张平行的 `qVoice` 表；
  `null` = 跟随当前音色（旁白），非空 = 角色固定音色，因此切旁白音色对角色句无影响；
- 短句合并的单元在**音色变化处截断**，不同角色不会被合进同一段音频；
- 预取按每个单元自己的音色分发，跨音色的相邻单元不启用 Edge 接棒（否则会串音）。

已知限制：一句里「旁白 + 台词」混排时不拆开（整句归角色）；
三字名可能被截成前两字（如「李世民」→「李世」），但同一角色始终一致；
点面板里的角色卡可手动换音色（写入 `rolebook`，跨章保持）。

音色槽上限 35 个（3 女 4 男 × 5 个音高档）。主要角色通常在 10 人以内的长篇里
轮不到复用；超出后按确定性规则复用同池音色，不会出现「同一角色两个声音」。

## 构建

环境：JDK 17、Android SDK（platform 34 / build-tools 34.0.0）、Gradle 8.5。

```bash
# 1. 把网页前端同步进 assets
bash sync-assets.sh

# 2. 编译 Debug APK
gradle assembleDebug --no-daemon
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

`local.properties` 需要指向本机 SDK，例如：

```properties
sdk.dir=/path/to/Android/sdk
```

CI：`.github/workflows/build-apk.yml` 会在 push 到 main 时自动打包并上传 artifact。
若该文件未能入库，可把 `ci/build-apk.yml` 移动回 `.github/workflows/` 目录。
